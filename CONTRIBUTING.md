# Contributing to Bsuir Time

Thanks for your interest in the project! Bug reports, feature ideas and pull
requests are all welcome.

## Getting started

Prerequisites: Node.js 20+, npm, Xcode (for iOS) or Android Studio + JDK 17
(for Android).

```bash
git clone https://github.com/vazonhub/bsuir-schedule.git
cd bsuir-schedule
npm install            # also installs git hooks (husky)
cp .env.example .env   # all variables are optional — see comments inside

npm run ios            # build & run on the iOS simulator
npm run android        # build & run on an Android emulator
```

> **Expo Go does not work** — the app uses `expo-router/unstable-native-tabs`
> (a native `UITabBarController`), which requires a dev client. `npm run ios`
> builds one for you. The telltale failure inside Expo Go is
> `<RNCTabView> Unimplemented component`.

## Checks

CI runs these on every PR — run them locally before pushing:

```bash
npm run format:check   # prettier
npm run lint           # eslint (0 warnings allowed)
npm run typecheck      # tsc --noEmit
npm test               # jest (unit tests)
```

The pre-commit hook (husky + lint-staged) runs prettier and `eslint --fix`
on staged files automatically.

### Tests

Unit tests cover the core logic in `src/utils` and run on [jest-expo].
Tests live in `src/**/__tests__/*.test.ts` next to the code they exercise.

```bash
npm test               # run once
npm run test:watch     # watch mode
npm run test:coverage  # with a coverage report
```

Aliases (`@utils/…`, `@theme`, …) resolve through the babel `module-resolver`
plugin — the same config the app uses — so imports in tests match the source.
When adding logic to a util, add or extend the matching `*.test.ts`.

[jest-expo]: https://docs.expo.dev/develop/unit-testing/

## Branches and pull requests

- **`develop`** is the default branch and where all development happens.
  Branch off it (`feature/*`, `fix/*`) and open your PR back into `develop`.
- `testing` and `master` are release-cycle branches — PRs into them are made
  by the maintainer only (see `RELEASE.md`).
- A PR must pass all CI checks. Use the PR template; describe **what** and
  **why**, attach screenshots for UI changes.

Commit messages follow [Conventional Commits](https://www.conventionalcommits.org/):
`feat: …`, `fix: …`, `chore: …`, `refactor: …`, `docs: …`. Scopes are
welcome: `fix(android-widget): …`, `feat(diary): …`.

## Architecture — MVC

The layering is strict; please don't cross it without discussing first:

- `src/models/dto/*` — DTO types for the `iis.bsuir.by/api/v1` responses.
- `src/services/api/*` — axios wrappers. HTTP requests happen **only** here.
- `src/stores/*` — Zustand stores (in-memory state).
- `src/controllers/*` — orchestration: API → normalization → store. The only
  place where the view layer meets services.
- `src/views/*` — screens: call controller methods, read stores via selectors.
- `src/components/*` — reusable UI without business logic.
- `app/*` — Expo Router 6 file-based routing; every route file is a thin
  re-export of a `@views/*` component.

Hard rules:

- No axios calls from view components.
- No hardcoded colors — only tokens from `@theme` (`Palette`, `Radius`,
  `Spacing`); lesson colors via `getLessonAccentColor` from `@utils/lesson`.
- Never edit `ios/` / `android/` by hand — they are generated by
  `expo prebuild`; native configuration belongs in `app.json` and the config
  plugins under `plugins/`.

More detail lives in `CLAUDE.md` (doubles as context for AI assistants and a
code-style reference).

## Code style

- TypeScript strict + `noUncheckedIndexedAccess` — check `arr[i]` for `undefined`.
- Imports: external libraries first, then `@`-aliases, then relative; use
  `import type` for type-only imports.
- Functional components without `React.FC`; props as a separate `interface Props`.
- `StyleSheet.create` for styles (or the `makeStyles(Palette)` factory for
  themed ones).
- Comments in English.

## Project services

- `services/auditory-api/` — a standalone Cloudflare Worker + nightly crawler
  that powers the "auditory free/busy" feature. It has its own README with
  deployment instructions; the app works fine without it.
